# Untangle V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a local Electron + Node worker app that inventories Messy, extracts by type queue, proposes categories via rules/Ollama, moves with journal/undo, and supports version pick-winner.

**Architecture:** Thin Electron/React UI talks IPC to a Node worker that owns SQLite, filesystem, extractors, Ollama client, and journaled moves.

**Tech Stack:** TypeScript, pnpm workspaces, Electron, React, Vite, better-sqlite3, Vitest, ExcelJS, mammoth, pdf-parse, Ollama HTTP API.

**Spec:** [docs/superpowers/specs/2026-11-10-untangle-design.md](../specs/2026-11-10-untangle-design.md)

## Global Constraints

- Local-only; no cloud classify.
- Never store full file bytes in SQLite or LLM prompts.
- Type order: XLSX → DOCX → PDF → PPTX → images → videos → other.
- Moves never overwrite; collision uses `name (n).ext`.
- Ollama optional; without it proposals become `needs_model`.
- Default model id: `qwen3:8b`.

## Review Focus

- Resume mid-scan after kill does not skip new files or blindly rehash unchanged rows.
- Move collision never overwrites; undo reverses when destination intact.
- Ollama garbage JSON → no move; status `needs_model`.
- Exact duplicate of moved file proposes same category / dupe flag.
- Cross-volume path uses copy+verify+delete.
